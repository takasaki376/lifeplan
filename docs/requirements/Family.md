# 家族情報管理機能 要件

## 1. 基本機能

- ユーザーごとに家族情報を登録・編集・削除できること
- 家族情報はクラウド（Firestore等）に保存されること
- 家族情報の取得・登録・更新・削除は認証済みユーザーのみ可能であること

## 2. 家族情報の項目

- 家族ID（自動採番またはFirestoreのドキュメントID）
- 氏名（必須）
- 続柄（例：本人、配偶者、子、親など／必須）
- 生年月日（必須）
- 性別（任意）
- 備考（任意）
- 作成日時・更新日時（自動記録）

## 3. UI要件

- 家族一覧をテーブルまたはカード形式で表示すること
- 家族の追加・編集フォームを提供すること
  - 氏名はテキスト入力
  - 続柄はプルダウンで選択
  - 生年月日は日付入力
  - 性別はラジオボタンやプルダウンで選択（任意）
  - 備考はテキスト入力（任意）
- 編集ボタンで既存家族情報の編集ができること
- 削除ボタンで家族情報を削除できること
- ローディング中はローダーを表示すること
- エラー発生時はエラーメッセージを表示すること

## 4. バリデーション

- 氏名・続柄・生年月日は必須
- 入力値に不備がある場合はエラーメッセージを表示

## 5. コード・API設計

- 型定義（TypeScript）を利用し、家族情報データの型安全性を担保
- API経由でCRUD操作を行う
- APIは認証トークン（Authorizationヘッダー）を検証し、ユーザーごとにデータを分離
- Firestore保存時はcreatedAt/updatedAtをTimestampで記録し、取得時はDate型に変換

## 6. その他

- Mantine UIを利用したユーザーインターフェース
- スマートフォン・PC両対応のレスポンシブデザイン
- 続柄は定数で管理し、日本語名称で表
